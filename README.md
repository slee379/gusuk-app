# 좋아하는 구석 — 독립 실행 앱(PWA)

**→ https://slee379.github.io/gusuk-app/**

Claude 아티팩트에서 떼어내, 컴퓨터와 폰 양쪽에 설치해 쓰는 웹앱.
사진과 메모는 **서버에 올라가지 않는다.** 웹에는 앱 껍데기만 올라간다.

```
gusuk-app/
├ index.html              앱 본체 — 이 파일이 원본(master)이다
├ privacy.html            개인정보처리방침 (구글 OAuth 게시에 필요)
├ manifest.webmanifest    앱 이름·아이콘·설치 정보
├ sw.js                   서비스 워커 (오프라인 실행). VERSION 은 자동 갱신됨
├ icons/                  홈 화면 아이콘 (make-icons.mjs 가 생성 — 직접 고치지 말 것)
├ deploy.ps1              배포 한 방
├ mcp/                    Claude 연결용 MCP 서버 (웹 배포와 무관)
└ tools/
   ├ sync-version.mjs     sw.js 버전 자동 갱신
   ├ make-icons.mjs       아이콘 생성 (색·형태를 바꾸고 다시 돌리면 전부 재생성)
   └ import-artifact.mjs  Claude 아티팩트 HTML 을 이 앱으로 들여올 때만 사용
```

## 아이콘

에두아르도 칠리다의 동판화에서 가져온 형태 — 따뜻한 종이 바탕에 먹빛,
서로 떨어진 네 덩어리와 그 사이의 흰 고랑. 왼쪽아래에 비워둔 자리가 "구석"이다.

색이나 형태를 바꾸려면 [`tools/make-icons.mjs`](tools/make-icons.mjs) 위쪽의
`PAPER` / `INK` / `SHAPES` 만 고치고 다시 돌리면 된다.

```bash
node tools/make-icons.mjs
```

`icons/` 안의 PNG 를 직접 고치지 마라. 다음 생성 때 덮어써진다.

## 리뉴얼하는 법

### 기본 경로 — 이 폴더의 `index.html` 을 직접 고친다

```powershell
.\deploy.ps1 "무엇을 고쳤는지"
```

이게 전부다. `deploy.ps1` 이 sw.js 버전을 알아서 새로 계산하고, 커밋하고, push 한다.
1~2분 뒤 반영된다. **주소는 그대로, 각 기기의 사진·메모도 그대로.**

배포 전에 뭐가 바뀌는지만 보고 싶으면:

```powershell
.\deploy.ps1 -Check
```

### 곁가지 — Claude 아티팩트 쪽에서 고쳤을 때

아티팩트에서 앱을 크게 뜯어고쳤다면, 그 HTML 을 받아서:

```powershell
node tools/import-artifact.mjs <받은HTML경로>
.\deploy.ps1 "아티팩트에서 리뉴얼"
```

`import-artifact.mjs` 는 Claude 런타임 제거·폴더모드 복원·서비스워커 주입을 **매번 다시** 적용한다.
치환할 곳을 하나라도 못 찾으면 아무것도 쓰지 않고 멈추고, 기존 `index.html` 은
`_backup/` 에 날짜별로 남겨둔다. 반쯤 망가진 앱이 배포되는 일은 없다.

먼저 `--dry` 를 붙이면 쓰지 않고 확인만 한다.

## 절대 바꾸면 안 되는 것 4가지

리뉴얼을 아무리 해도 이 넷만 그대로면 데이터도 주소도 안전하다.

| | 무엇 | 바꾸면 생기는 일 |
|---|---|---|
| 1 | **주소의 도메인** (`slee379.github.io`) | 브라우저 저장소는 도메인 단위다. 도메인이 바뀌면 **그 기기의 기록이 안 보인다.** 커스텀 도메인을 붙일 생각이면 사진을 넣기 전에 정하고, 이미 넣었다면 반드시 `백업 저장` → 새 주소에서 `불러오기` |
| 2 | `index.html` 의 `DB_NAME = "gusuk-archive"` | 저장소 이름이 바뀌어 기존 기록을 못 찾는다 |
| 3 | `manifest.webmanifest` 의 `"id"` | 설치된 앱이 별개 앱으로 인식돼 홈 화면에 하나 더 생긴다 |
| 4 | 백업 JSON 의 `app:"gusuk"` / `v:1` 형식 | 예전에 저장해둔 백업 파일을 못 읽게 된다 |

레포 **이름**은 (도메인이 아니므로) 데이터에 영향이 없지만, 바꾸면 주소 경로가 달라져서
이미 설치한 앱 아이콘이 깨진다. 그냥 두는 게 좋다.

## 왜 리뉴얼해도 사진이 안 날아가는가

앱 파일과 데이터는 **완전히 다른 곳**에 있다.

- **앱 파일** (`index.html` 등) → 웹서버 + 서비스 워커 캐시. 배포할 때마다 갈아치워진다.
- **사진·메모** → 각 기기의 IndexedDB(`gusuk-archive`) 또는 연결한 폴더. 배포가 건드리지 않는다.

서비스 워커 캐시를 통째로 지워도 기록은 남는다. 둘은 별개 저장소다.

불러오기도 안전하게 짜여 있다 — 백업을 두 번 넣어도 사진 id 로 중복을 걸러내고,
태그는 id 가 아니라 **이름으로** 다시 매칭한다. 그래서 앱 구조가 바뀐 뒤에 옛날 백업을
넣어도 태그가 제자리를 찾아간다.

## 데이터가 있는 곳 · 옮기는 법

- **컴퓨터 (Chrome·Edge)** — 첫 실행 때 구글 드라이브 안의 빈 폴더를 고르면, 사진·메모가
  그 폴더에 실제 파일로 쌓인다. 드라이브가 다른 컴퓨터로 옮겨주고, 거기서 같은 폴더를
  연결하면 이어서 쓴다. **이 폴더 자체가 가장 튼튼한 백업이다.**
- **폰** — 폴더 API 를 지원하는 모바일 브라우저가 없어서 브라우저 저장만 된다.
  옮길 때는 `백업 저장` → 드라이브 → 폰에서 `불러오기`.

### 폰에서 폴더 권한이 매번 뜨는 이유

안드로이드 크롬은 폴더 권한을 **그 세션 동안만** 준다 (「until you close all tabs」).
폴더 자체는 기억되므로 다시 고를 필요는 없지만, **허용은 다시 눌러야 한다.**
`requestPermission()` 은 사용자의 손가락질 없이는 부를 수 없다 — 브라우저 규칙이라 우회할 수 없다.

그래서 대신 **막지 않기로** 했다. 폴더를 읽을 때마다 사본(`vaultMirror` + `th:` 썸네일)을
브라우저 안에 떠 두고, 권한이 없는 동안에는 그 사본으로 **보기만** 된다.
위에 얇은 띠로 `보기만 · 폴더 잠김` 이 뜨고, 고치려 하면 그 손가락질을 그대로 써서 권한을 청한다.

사본은 폴더로 되돌려 쓰지 않는다. 그래서 원본이 상할 일이 없다.

⚠️ **아이폰**: iOS 는 오래 안 쓴 사이트 데이터를 지우는데, **홈 화면에 추가한 앱은 그 대상에서 빠진다.**
사파리 탭이 아니라 꼭 설치해서 쓸 것.

## 공간 (여러 장 묶기)

같은 자리를 각도만 달리해 찍은 사진들을 하나로 묶는다.
「모든 구석」에서는 낱장이 아니라 **공간 카드 하나**로 접혀 보이고, 눌러서 들어가면 그 안의 사진들이 펼쳐진다.

성격이 갈린다 — 이게 설계의 핵심이다.

| | 담는 것 |
|---|---|
| **공간** | 객관: 이름, 메모, **사실**(바닥·조명·시기처럼 취향이 아닌 것) |
| **사진** | 주관: 왜 좋았는지, 부분 메모, 취향 태그 |

객관 정보를 위해 화면을 따로 만들지 않은 이유가 이것이다. 필요한 건 별도의 *공간*이 아니라
별도의 *필드*였고, 그게 공간의 「사실」이다. 한 구석에 대한 정보가 두 군데로 흩어지지 않는다.

묶는 방법은 세 갈래다. 한 장씩 넣는 게 번거로워서 나머지 둘을 냈다.

| 방법 | 언제 |
|---|---|
| 사진 상세 패널의 **공간** 칸에서 고르기 | 한 장만 옮길 때 |
| 아카이브 머리의 **「공간으로 묶기」** → 여러 장 골라 한 번에 | 이미 올려 둔 것들을 묶을 때 |
| 아카이브 머리의 **「+ 새 공간」** → 공간부터 만들고 그 안에서 올리기 | 한 자리를 여러 장 찍어 왔을 때 |

- **「공간으로 묶기」** 를 누르면 공간 카드가 낱장으로 펼쳐지고 카드마다 체크가 뜬다.
  누르는 대로 골라서 아래 막대에서 **새 공간으로 묶기 / 기존 공간에 넣기 / 묶음에서 빼기** 를 고른다.
  「보이는 것 모두」로 거른 결과를 통째로 담을 수도 있다. `Esc` 로 그만둔다.
- **「+ 새 공간」** 으로 만든 공간은 **비어 있어도 남는다.** 그 안에서 올린 사진은
  자동으로 그 공간에 담기므로, 찍어 온 걸 한 번에 부어 넣으면 된다.
- 공간에서 나오는 길은 둘 — 제목 바로 위의 **「← 모든 구석」**, 또는 상단의 **「아카이브」** 탭.
  상단 「아카이브」는 화면 전환이자 *처음 자리로* 라는 뜻이라, 공간에서 빠져나오고 걸어둔 태그·검색도 함께 푼다 (`Esc` 도 같다)
- 공간에 들어가면 이름·메모·**공간 태그**·사실을 그 자리에서 고친다
- 공간 안에서도 **「좋아하는 부분만」** 이 통한다 — 그 공간의 조각들만 모인다

### 공간 태그 — 한 번 달면 식구들이 물려받는다

공간에도 태그를 단다. 사진마다 되풀이해 적기 아까운 것들 —
`#성수동` `#프랭크로이드라이트` `#2024년` 처럼 **어디·누구의 것·언제** 같은,
장면이 아니라 출처에 붙는 말이 여기 자리다.

공간에 단 태그는 **그 안의 사진이 모두 물려받는다.**

- 태그로 거르면 그 공간의 사진이 전부 걸린다 (「사진으로」·「좋아하는 부분만」 양쪽)
- 태그 목록의 숫자와 그래프의 태그 노드도 물려받은 몫까지 센다
- 사진 상세에서는 **「이 공간에서 물려받음」** 으로 보여주기만 한다 —
  한 장에서만 떼어낼 수는 없다. 떼려면 공간에서 떼야 한다
- 그래프에서 공간 노드가 서 있으면 공간 태그는 **공간 노드에 한 번만** 걸린다.
  식구 사진마다 같은 선을 되풀이하면 판이 실타래가 되기 때문이다
  (「같은 공간끼리 묶기」를 끄면 사진 쪽에 직접 걸린다)

이름 고치기·합치기·지우기는 사진 태그와 똑같이 동작하고, 공간에 붙은 것까지 함께 따라간다.
저장은 `spaces.json` 에 **이름으로** 적힌다 (노트의 태그와 같은 이유 — id 는 기기마다 다르니까).

코드로는 `ownTagIds()` 가 사진 자신의 것, `itemTagIds()` 가 물려받은 것까지다.
- 태그로 거르면 공간 카드에 `1 / 3장` 처럼 몇 장이 걸렸는지 나온다
- 사진이 하나도 안 남은 공간은 저절로 사라진다 (태그와 같은 규칙).
  단 손으로 만들어 둔 공간은 `keep` 표시가 붙어 비어 있어도 살아남는다

저장 위치: 볼트 모드에서는 `spaces.json` 에 이름·메모·사실이,
어떤 사진이 어느 공간인지는 각 노트의 `space` 필드에 있다 — **진실은 한 곳에만 적는다.**

## 좋아하는 부분 표시 — 네모 / 자동

상세 화면 위쪽에서 방법을 고른다.

- **네모로** — 드래그해서 사각형. 만든 뒤에는 골라서 모서리 손잡이로 크기 조절, 안쪽을 끌어 이동.
- **자동으로** — 누른 곳의 **색이 이어지는 면**을 따낸다. 벽·상판·목재 패널처럼 "면"에 강하다.
  「잡는 범위」 슬라이더로 넓히거나 좁힌 뒤 `이대로 담기`.

자동 선택은 **사물 인식이 아니다.** 색의 연속을 따라갈 뿐이라 "의자"를 알아보지는 못한다.
대신 모델을 받지 않으므로 오프라인에서 즉시 동작하고, 사진은 어디로도 나가지 않는다.
소재와 면을 모으는 이 앱에는 사물 인식보다 이쪽이 더 맞는다.

동작 순서: 축소 → 클릭한 색과 비슷한 곳으로 번지기(flood fill) → 잔구멍 메우기 →
클릭한 덩어리만 남기기 → 테두리 따기(marching squares) → 점 줄이기(Douglas-Peucker) → 다각형.

저장은 기존 형식에 `path` 필드만 **추가**했다. `x/y/w/h` 는 경계상자로 그대로 남아서
옛 백업도 읽히고, 다각형은 `clip-path` 로 그린다 — 퍼센트라서 크기를 조절해도 모양이 따라 늘어난다.

## 태그 자동 제안

사진을 열면 그 사진의 **주된 색을 기기 안에서 읽어** 태그 후보를 띄운다.
누르면 바로 태그가 된다.

- 뽑아내는 것: 주된 색 최대 3개, 색온도(따뜻함·서늘함), 밝기(밝음·어둑함)
- **뽑아내지 못하는 것**: 사물·재질·구조. 아치·라임스톤·고요함 같은 건
  장면을 이해해야 하는 일이라 색 분석으로는 불가능하다.
- 사진은 어디로도 전송되지 않는다. k-means 로 대표색을 구하고 색 이름을 붙일 뿐이다.
- 결과는 메모리에만 둔다 — 백업 형식(`app:"gusuk"`, `v:1`)을 건드리지 않기 위해서다.

색 이름 사전을 고치려면 `index.html` 의 `nameColor()` 를 보면 된다.

### 이런 것도 자주 같이

색 다음 줄에는 **내 기록에서 배운 추천**이 뜬다. 올리브를 붙인 사진들에 늘 오크와
간접조명이 같이 있었다면, 새 올리브 사진에 그 둘을 권한다. 왜 권하는지도 함께 보여준다
(「‘올리브’ 붙인 사진 4장에 같이 있었어요」).

- 씨앗은 **사진에서 읽은 색 + 이 사진에 이미 붙인 태그**. 그래서 하나 붙일 때마다 추천이 좋아진다
- **내 어휘 안에서만** 고른다 — 없는 말을 지어내지 않는다
- 두 번 이상 겹친 것만, 그리고 **들림(lift)이 1.15 이상**인 것만 — 아무 데나 붙는 흔한 태그는 걸러진다
- 사진이 3장 미만이면 조용하다 (우연이 지배하므로)

브랜드나 건물 이름 같은 건 이 방식으로는 나오지 않는다. 그건 외부 AI가 필요한 일이고,
사진을 밖으로 보내야 하며, **모를 때 지어내는** 문제가 따라온다.

## 무드보드

세 번째 탭. **재질과 색만 남기고 글자를 걷어낸 판.** 새 프로젝트를 시작할 때
마음에 든 조각들을 모아 놓고 서로 어울리는지 눈으로 견주는 화면이다.

- **골라 담기** — 아무것이나 한꺼번에 쓸어 담지 않는다. 늘 같은 네 걸음이다

  | | |
  |---|---|
  | **1. 구성물 담기** | 아카이브 머리의 버튼. 카드마다 체크가 뜬다 |
  | **2. 고르기 / 모든 선택 취소** | 눌러서 고른다. 「보이는 것 모두」로 거른 결과를 통째로 |
  | **3. 무드보드 고르기** | 아래 막대의 목록에서. 새 보드를 그 자리에서 만들 수도 있다 |
  | **4. 담기** | 고른 것만 그 보드로 |

  **「사진으로」와 「좋아하는 부분만」 양쪽에서** 고를 수 있다 — 사진 한 장을 통째로 담을지,
  그 안의 조각만 담을지가 갈리는 자리라서다. `Esc` 로 그만둔다.

- **무드보드 안에서 바로 담기** — 판 위의 **「구성물 담기」** 를 누르면 창이 뜬다.
  사진과 부분이 한자리에 펼쳐지고, 고른 것은 곧바로 그 보드에 담긴다.
  조합을 짜다가 "저것도 넣어볼까" 가 생기는 자리가 여기라서, 아카이브로 나가지 않아도 된다.
  이미 담긴 것은 **「담김」** 으로 잠겨 있다 (빼는 일은 판 위에서 한다)

- **한 장씩 바로 담기** — 생각났을 때 곧장 담을 수 있게 지름길도 열어뒀다

  | 방법 | 어디서 |
  |---|---|
  | 카드 오른쪽 위 **핀 버튼** | 전부 |
  | 카드에 **우클릭** → 메뉴 (어느 보드에 담을지 고를 수 있다) | 컴퓨터 |
  | 카드를 **길게 누르기** → 같은 메뉴 | 폰 |
  | 카드에 마우스를 올린 채 **`P`** | 컴퓨터 |

  보드가 하나도 없으면 알아서 만들어 준다. 사진 상세의 부분 메모 줄에도 핀이 있다.
- **보드는 여러 개** — 프로젝트마다 하나씩. 위에서 골라 전환
- **자유 판** — 격자에 줄 세우지 않는다. 피그마처럼 조각을 아무 데나 놓고 끌어다 견준다.
  붙여 보고, 떼어 보고, 크기를 달리해 보는 일이 곧 조합을 고르는 일이라서다

  | 손놀림 | 하는 일 |
  |---|---|
  | 조각을 **끌기** | 옮기기 (잡은 것이 맨 위로 온다) |
  | 오른쪽 아래 **모서리를 끌기** | 크기 바꾸기 — 재질이 읽힐 때까지 키운다 |
  | 빈 곳을 **끌기** | 판 자체를 움직이기 |
  | **Ctrl+휠** · 두 손가락 · 오른쪽 아래 `+ −` | 확대·축소 |
  | 조각을 **두 번 누르기** | 원본 사진 열기 |
  | 조각을 고르고 **`Delete`** · 조각 위 **×** | 보드에서 빼기 |
  | **「정돈」** | 흐트러진 걸 다시 줄 세우기 |
  | **「화면 맞춤」** · `⤢` | 담긴 걸 한 화면에 |

  자리와 크기는 핀에 함께 적히므로 (`x`·`y`·`w`) 다음에 열어도 그대로다.
  판을 보던 위치와 배율은 보드마다 기억한다.
- **태그 요약 띠** — 담긴 조각들의 태그를 부문별로 위에 눕혀 둔다
- **이미지로 저장** — 판에 놓인 그대로 한 장의 PNG로.
  시공사나 친구에게 그대로 보낼 수 있다

「좋아하는 부분만」으로 보면 재질 조각이 바로 나오므로 그 상태에서 담는 게 빠르다.

핀은 원본을 복사하지 않고 **가리키기만 한다.** 사진이나 부분을 지우면 핀도 함께 사라지고,
보드를 지워도 사진과 메모는 그대로 남는다.

저장 위치: 볼트 모드에서는 `boards.json`. 백업 JSON 에도 `boards` 로 들어가며,
불러올 때는 **이름이 같은 보드끼리 핀을 합친다.**

## 자동 선택 — 테두리에서 멈춰 물체를 따낸다

예전 마술봉은 **색이 이어지는 만큼** 번졌다. 그래서 물체를 넘어 배경까지 새어 나가거나,
그늘이 진 자리에서 끊겼다. 이제는 번지기 전에 **테두리 지도**를 먼저 그린다.

- **소벨(Sobel)** 로 밝기가 급히 꺾이는 자리를 찾아 둔다 — 사람이 물체를 알아보는
  첫 단서가 색이 아니라 경계라서다
- 번짐은 그 선을 **넘지 못한다.** 허용 오차를 아무리 올려도 테두리는 지킨다
- 받아들이는 갈래가 둘이다 — 처음 누른 색과 가깝거나(허용 오차),
  **바로 옆 칸과 가깝거나**(그 절반). 뒤쪽 갈래가 있어 그늘이 서서히 지는 면도
  끊기지 않고 따라간다
- 테두리 앞에서 한 칸 멈춰 서므로, 마지막에 한 칸 부풀려 윤곽선을 품는다

모델도 내려받을 것도 없는 산수라서 즉시 돈다. 코드는 `wandEdges()` / `floodMask()`.

### 따낸 자리는 배경 없는 그림이 된다

골라낸 마스크를 **알파 채널로 구워** 넣는다. 결과는 PNG 처럼 물체만 떠 있는 그림이다 —
무드보드에 올렸을 때 네모난 배경이 따라붙지 않는다. 가장자리는 마스크를 이중선형으로
읽어 부드럽게 깎는다(계단처럼 각지면 오려 붙인 티가 난다).

- 웹P를 지원하면 웹P, 아니면 PNG 로 굽는다 (둘 다 투명을 담는다)
- 무드보드에서는 **바탕도 그림자도 없이** 떠 있고, 「이미지로 저장」에도 그대로 나간다
- 마음에 안 들면 부분 메모 줄의 **「빼기」** — 원본에서 잘라낸 네모로 돌아간다

## 부분에 깔끔한 사진 붙이기

자동 선택이 잘 듣지 않는 장면도 있다. 테두리가 흐릿하거나, 물체가 배경과 같은 색이거나.
그럴 때를 위해 부분마다 **사진 한 장을 따로 붙일 수 있게** 했다.
제품 컷이든, 다른 데서 깔끔하게 잘라 온 그림이든.

- 부분 메모 줄의 **「깔끔한 사진 넣기」**
- 배경이 뚫린 PNG 를 넣으면 **투명한 채로** 지켜진다 (jpeg 로 굽지 않고 형식을 바꾼다)
- 붙이면 그 사진이 **그 부분의 얼굴**이 된다 — 아카이브의 부분 카드, 무드보드 조각,
  그래프 노드, 무드보드 이미지 저장까지 전부
- 안 붙이면 여태처럼 원본에서 잘라낸 자리를 쓴다
- **「빼기」** 를 누르면 원본 자리로 돌아간다. 원본 사진과 네모의 위치는 그대로 남으므로
  "이 물건이 사진의 어디에 있었나" 는 잃지 않는다

붙인 사진도 기기 안에 그대로 있다. 볼트(폴더) 모드에서는
`images/<사진id>__<부분id>.webp` 로 따로 저장되고, 노트에는 파일 이름만 적힌다.
백업 파일에도 함께 담기므로 다른 기기에서 되살릴 수 있다.

> **왜 학습된 모델을 쓰지 않았나**
> 브라우저 안에서 도는 물체 분할 모델(SlimSAM 등)이 있기는 하다. 다만 가중치만
> 14MB 남짓에 실행기까지 더하면 30MB를 넘고, 첫 사용 때 내려받아야 하며 폰에서는
> 느리다. 사진 한 장 담는 데 그만한 짐을 지우는 것보다, 테두리를 읽는 산수로
> 대부분을 해결하고 안 되는 자리만 손으로 채우는 편이 이 앱의 몸집에 맞다고 봤다.

## 취향 그래프 — 조합 찾기

두 가지 단위로 볼 수 있다.

- **사진으로** — 사진 노드 + 태그 노드
- **부분까지** — 사진에서 **좋아하는 부분이 갈라져 나온다.** 부분 노드는 실제 잘린 조각으로
  그려지고(자동 선택한 면이면 그 모양대로), 태그는 사진과 부분 **양쪽에** 붙는다.

취향의 단위는 사진이 아니라 부분이다. 사진 한 장에는 서로 다른 이유로 좋아한 것들이
섞여 있기 때문에, 조합을 짜려면 그 알갱이들이 노드여야 한다.

### 태그끼리 잇기 — "무엇이 무엇과 어울리나"

**같은 자리에서 함께 쓰인** 태그끼리 선을 긋는다. 여기서 '같은 자리'란
사진 한 장(사진으로 모드) 또는 좋아하는 부분 하나(부분까지 모드)다.

- 두 태그가 **두 번 이상** 같은 자리에 함께 붙었을 때만 선이 그어진다.
  한 번은 우연일 수 있어서다 (`OPT.thr`, 슬라이더로 조절)
- 함께 나온 횟수가 많을수록 **굵고 짧아진다** — 굵은 선끼리는 서로 끌어당겨 뭉친다

읽는 법: `오크 ↔ 간접조명` 이 굵게 이어져 있다면, 내가 좋다고 표시한 자리에서
그 둘이 거듭 함께 있었다는 뜻이다. 취향에서 한 쌍으로 굳은 조합이다.
새 프로젝트의 재료를 고를 때 이 선을 따라가면 된다.

태그 사이의 선이지 사진 사이의 선이 아니라는 점이 「닮은 것끼리 잇기」와 다르다.
그쪽은 *사진(또는 부분)* 끼리 겹치는 태그 수로 잇는다.

### 같은 공간끼리 묶기

켜 두면 (기본값) 한 공간에 묶인 사진들이 그래프에서도 한 덩어리가 된다.
가운데에 그 공간의 대표 사진이 **동그란 노드**로 서고, 짧고 굵은 선이 식구들을 끌어당긴다.
아카이브에서는 하나로 접혀 있는 것이 그래프에서만 따로 놀면 같은 자료를 두 가지로 말하는 셈이라서다.
공간 노드를 누르면 그 공간으로 바로 들어간다.

### 노드 얼굴 — 따낸 그림이 있으면 그것을 쓴다

부분에서 배경을 지운 그림을 얻었거나 손으로 사진을 붙였으면, **그 사진이 그 자리의
얼굴**이 된다. 부분 노드는 물론 **원본 사진 노드도** 같은 그림을 쓴다 —
원본과 따낸 그림을 굳이 둘로 갈라 보여줄 이유가 없어서다.
배경이 지워진 그림은 네모 테두리 없이 통째로 띄운다.

### 노드 크기 = 담긴 내용의 양

부분이 여럿이고 태그가 많고 메모가 긴 것일수록 크다. 눈이 먼저 가는 것이
실제로 많이 들여다본 것과 같아야 그래프를 훑는 일에 쓸모가 있다.

기준은 **같은 종류끼리의 평균**이다. 평균만큼 담긴 것이 여태 쓰던 크기가 되고,
그보다 적게 담긴 것은 작아지고 많이 담긴 것은 커진다 (아래위로 각각 절반·두 배쯤에서 멈춘다).
평균에 맞추므로 사진이 늘어도 그래프 전체의 밀도는 그대로다.

| 노드 | 무엇을 세는가 |
|---|---|
| 사진 | 부분 수 · 태그 수 · 메모 길이 · 이어둔 사진 수 |
| 좋아하는 부분 | 그 부분의 태그 수 · 메모 길이 |
| 태그 | 붙어 있는 자리의 수 |
| 공간 | 묶인 사진들의 내용을 합한 양 |

크기 상수는 `index.html` 의 `NAVG` / `NMIN`, 계산은 `relSize()` 에 있다.

왼쪽 위 설정 판은 제목 옆의 **−** 로 접을 수 있다. 접으면 같은 자리에 작은 손잡이만 남는다.

## 태그 고치기 (이름·부문)

마크다운에서 `#` 뒤에 적고 Enter 로 태그를 만드는 그 손놀림 그대로,
**이미 붙은 태그도 그 자리에서 고친다.**

- 사진 상세의 태그 칸에서 **칩의 이름을 누르면** `#` 뒤가 입력칸으로 바뀐다.
  고쳐 쓰고 `Enter` 면 확정, `Esc` 면 되돌린다
- 이름을 고치면 **붙어 있는 모든 곳에 반영**된다 (오타 수정)
- 이미 있는 이름을 적으면 **하나로 합쳐진다**
- 입력칸에 `#` 를 앞에 붙여 적어도 그대로 받는다 (`#오크` → `오크`)

왼쪽 태그 목록 위의 **정리** 를 누르면 목록 전체를 한눈에 놓고 고칠 수 있다 —
이름, 부문, 지우기.

### 부문은 이름에서 저절로 정해진다

`노랑` 이라고만 적어도 **색** 부문으로 들어간다. 부문을 일일이 고르지 않기 위한 것이다.

- 판정은 두 갈래 — 이름 안에 든 낱말(`CATWORDS`)과 끝맺음 꼴(`CATPATS`).
  여러 갈래에 걸리면 **더 길게 맞은 쪽**이 이긴다.
  그래서 `조명갓` 은 빛(조명)이 아니라 가구로, `마감재` 는 디테일(마감)이 아니라 소재로 간다
- 이름을 고치면 부문도 다시 본다. 단 **손으로 부문을 고른 적이 있으면 그 부문을 지킨다**
  (`tags.json` 에 `manual: true` 로 남는다)
- 옛 기록의 「기타」 태그는 앱을 열 때 한 번 조용히 다시 짚어 준다.
  전체를 다시 맞추려면 **정리 → 「이름에서 부문 다시 맞추기」**

사전을 고치려면 `index.html` 의 `CATWORDS` / `CATPATS` / `guessCat()` 을 보면 된다.

⚠️ 볼트 모드에서 노트는 태그를 **이름으로** 저장한다. 그래서 이름을 바꾸면 그 태그가 붙은
노트를 전부 다시 쓴다. 안 그러면 다음 동기화 때 옛 이름이 되살아난다.

## Claude · 옵시디언과 연결

`mcp/` 에 MCP 서버가 있다. Claude 가 아카이브를 직접 읽고 쓰게 해준다 —
태그 정리, 공통점 찾기, 옵시디언으로 마크다운 내보내기.

**단, 폴더 모드일 때만 된다.** 브라우저 안(IndexedDB)에 있는 기록은
샌드박스 밖에서 읽을 방법이 없다. 폰의 기록은 `백업 저장` → 컴퓨터에서 `불러오기` 를 거쳐야 한다.

설치와 도구 목록은 [`mcp/README.md`](mcp/README.md) 참고.

## 폰 화면

폭 820px 이하에서는 왼쪽 태그 사이드바가 **아래에서 올라오는 시트**로 바뀐다.
상단바 필터 버튼(고른 태그 수가 배지로 표시됨)으로 열고, 시트 밖을 누르거나 `닫기`로 닫는다.
검색·태그·태그조합·백업 버튼이 전부 그 안에 들어 있다.

**HTTPS 가 필수다** — 서비스 워커와 앱 설치는 https(또는 localhost)에서만 동작한다.
`_backup/` 은 `.gitignore` 로 빠지고, `.nojekyll` 이 있어 Jekyll 처리를 건너뛴다.

## 로컬에서 확인

```bash
python -m http.server 8123 --directory gusuk-app
```

`http://localhost:8123`. `index.html` 을 파일로 직접 열어도 앱은 뜨지만,
`file://` 에서는 서비스 워커가 등록되지 않아 설치·오프라인은 안 된다.
