# 좋아하는 구석 — 독립 실행 앱(PWA)

**→ https://slee379.github.io/gusuk-app/**

Claude 아티팩트에서 떼어내, 컴퓨터와 폰 양쪽에 설치해 쓰는 웹앱.
사진과 메모는 **서버에 올라가지 않는다.** 웹에는 앱 껍데기만 올라간다.

```
gusuk-app/
├ index.html              앱 본체 — 이 파일이 원본(master)이다
├ privacy.html            개인정보처리방침 (구글 OAuth 게시에 필요)
├ manifest.webmanifest    앱 이름·아이콘·설치 정보
├ sw.js                   서비스 워커 (오프라인 실행). VERSION 은 자동 갱신됨
├ icons/                  홈 화면 아이콘 (make-icons.mjs 가 생성 — 직접 고치지 말 것)
├ deploy.ps1              배포 한 방
└ tools/
   ├ sync-version.mjs     sw.js 버전 자동 갱신
   ├ make-icons.mjs       아이콘 생성 (색·형태를 바꾸고 다시 돌리면 전부 재생성)
   └ import-artifact.mjs  Claude 아티팩트 HTML 을 이 앱으로 들여올 때만 사용
```

## 아이콘

에두아르도 칠리다의 동판화에서 가져온 형태 — 따뜻한 종이 바탕에 먹빛,
서로 떨어진 네 덩어리와 그 사이의 흰 고랑. 왼쪽아래에 비워둔 자리가 "구석"이다.

색이나 형태를 바꾸려면 [`tools/make-icons.mjs`](tools/make-icons.mjs) 위쪽의
`PAPER` / `INK` / `SHAPES` 만 고치고 다시 돌리면 된다.

```bash
node tools/make-icons.mjs
```

`icons/` 안의 PNG 를 직접 고치지 마라. 다음 생성 때 덮어써진다.

## 리뉴얼하는 법

### 기본 경로 — 이 폴더의 `index.html` 을 직접 고친다

```powershell
.\deploy.ps1 "무엇을 고쳤는지"
```

이게 전부다. `deploy.ps1` 이 sw.js 버전을 알아서 새로 계산하고, 커밋하고, push 한다.
1~2분 뒤 반영된다. **주소는 그대로, 각 기기의 사진·메모도 그대로.**

배포 전에 뭐가 바뀌는지만 보고 싶으면:

```powershell
.\deploy.ps1 -Check
```

### 곁가지 — Claude 아티팩트 쪽에서 고쳤을 때

아티팩트에서 앱을 크게 뜯어고쳤다면, 그 HTML 을 받아서:

```powershell
node tools/import-artifact.mjs <받은HTML경로>
.\deploy.ps1 "아티팩트에서 리뉴얼"
```

`import-artifact.mjs` 는 Claude 런타임 제거·폴더모드 복원·서비스워커 주입을 **매번 다시** 적용한다.
치환할 곳을 하나라도 못 찾으면 아무것도 쓰지 않고 멈추고, 기존 `index.html` 은
`_backup/` 에 날짜별로 남겨둔다. 반쯤 망가진 앱이 배포되는 일은 없다.

먼저 `--dry` 를 붙이면 쓰지 않고 확인만 한다.

## 절대 바꾸면 안 되는 것 4가지

리뉴얼을 아무리 해도 이 넷만 그대로면 데이터도 주소도 안전하다.

| | 무엇 | 바꾸면 생기는 일 |
|---|---|---|
| 1 | **주소의 도메인** (`slee379.github.io`) | 브라우저 저장소는 도메인 단위다. 도메인이 바뀌면 **그 기기의 기록이 안 보인다.** 커스텀 도메인을 붙일 생각이면 사진을 넣기 전에 정하고, 이미 넣었다면 반드시 `백업 저장` → 새 주소에서 `불러오기` |
| 2 | `index.html` 의 `DB_NAME = "gusuk-archive"` | 저장소 이름이 바뀌어 기존 기록을 못 찾는다 |
| 3 | `manifest.webmanifest` 의 `"id"` | 설치된 앱이 별개 앱으로 인식돼 홈 화면에 하나 더 생긴다 |
| 4 | 백업 JSON 의 `app:"gusuk"` / `v:1` 형식 | 예전에 저장해둔 백업 파일을 못 읽게 된다 |

레포 **이름**은 (도메인이 아니므로) 데이터에 영향이 없지만, 바꾸면 주소 경로가 달라져서
이미 설치한 앱 아이콘이 깨진다. 그냥 두는 게 좋다.

---

## 왜 리뉴얼해도 사진이 안 날아가는가

앱 파일과 데이터는 **완전히 다른 곳**에 있다.

- **앱 파일** (`index.html` 등) → 웹서버 + 서비스 워커 캐시. 배포할 때마다 갈아치워진다.
- **사진·메모** → 각 기기의 IndexedDB(`gusuk-archive`) 또는 연결한 폴더. 배포가 건드리지 않는다.

서비스 워커 캐시를 통째로 지워도 기록은 남는다. 둘은 별개 저장소다.

불러오기도 안전하게 짜여 있다 — 백업을 두 번 넣어도 사진 id 로 중복을 걸러내고,
태그는 id 가 아니라 **이름으로** 다시 매칭한다. 그래서 앱 구조가 바뀐 뒤에 옛날 백업을
넣어도 태그가 제자리를 찾아간다.

## 데이터가 있는 곳 · 옮기는 법

- **컴퓨터 (Chrome·Edge)** — 첫 실행 때 구글 드라이브 안의 빈 폴더를 고르면, 사진·메모가
  그 폴더에 실제 파일로 쌓인다. 드라이브가 다른 컴퓨터로 옮겨주고, 거기서 같은 폴더를
  연결하면 이어서 쓴다. **이 폴더 자체가 가장 튼튼한 백업이다.**
- **폰** — 폴더 API 를 지원하는 모바일 브라우저가 없어서 브라우저 저장만 된다.
  옮길 때는 `백업 저장` → 드라이브 → 폰에서 `불러오기`.

⚠️ **아이폰**: iOS 는 오래 안 쓴 사이트 데이터를 지우는데, **홈 화면에 추가한 앱은 그 대상에서 빠진다.**
사파리 탭이 아니라 꼭 설치해서 쓸 것.

## 사진 담는 방법

| 방법 | 어디서 |
|---|---|
| `+` 버튼 → 사진첩 / 파일 | 전부 |
| 📷 버튼 → 카메라 바로 열기 | 폰 (상단바) |
| 드래그해서 놓기 | 컴퓨터 |
| Ctrl+V 붙여넣기 | 컴퓨터 |
| 사진 앱에서 **공유 → 좋아하는 구석** | **안드로이드만** — iOS 는 웹앱 공유 타겟을 지원하지 않는다 |
| 홈 화면 아이콘 **길게 누르기 → 촬영** | 안드로이드 |

## 태그 자동 제안

사진을 열면 그 사진의 **주된 색을 기기 안에서 읽어** 태그 후보를 띄운다.
누르면 바로 태그가 된다.

- 뽑아내는 것: 주된 색 최대 3개, 색온도(따뜻함·서늘함), 밝기(밝음·어둑함)
- **뽑아내지 못하는 것**: 사물·재질·구조. 아치·라임스톤·고요함 같은 건
  장면을 이해해야 하는 일이라 색 분석으로는 불가능하다.
- 사진은 어디로도 전송되지 않는다. k-means 로 대표색을 구하고 색 이름을 붙일 뿐이다.
- 결과는 메모리에만 둔다 — 백업 형식(`app:"gusuk"`, `v:1`)을 건드리지 않기 위해서다.

색 이름 사전을 고치려면 `index.html` 의 `nameColor()` 를 보면 된다.

## 폰 화면

폭 820px 이하에서는 왼쪽 태그 사이드바가 **아래에서 올라오는 시트**로 바뀐다.
상단바 필터 버튼(고른 태그 수가 배지로 표시됨)으로 열고, 시트 밖을 누르거나 `닫기`로 닫는다.
검색·태그·태그조합·백업 버튼이 전부 그 안에 들어 있다.

`_backup/` 은 `.gitignore` 로 빠지고, `.nojekyll` 이 있어 Jekyll 처리를 건너뛴다.

## 로컬에서 확인

```bash
python -m http.server 8123 --directory gusuk-app
```

`http://localhost:8123`. `index.html` 을 파일로 직접 열어도 앱은 뜨지만,
`file://` 에서는 서비스 워커가 등록되지 않아 설치·오프라인은 안 된다.
